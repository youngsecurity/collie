## Operator impact

Pairing now gates API reads as well as writes.

```bash
# From the installed checkout on the host:
bin/collie pair
```

> **Warning.** A browser that was never paired can no longer read panes after this update.
> Enter the host's pairing code on that browser. Revoking the last device does not reopen access.

Existing valid pairings continue to work. The local CLI gets a separate host-only read
credential; it is not a replacement for browser pairing. Header-based write restrictions
remain independent. See [ADR 0086](../../.adr/0086-reads-need-the-pairing-token.md).

Session copies now use a bounded IndexedDB store. Saved copies cannot send commands, and
unpairing, revocation and expiry trigger the shared wipe path. See
[ADR 0087](../../.adr/0087-the-on-device-store-is-one-thing.md).

## Fork reconciliation

Upstream features must not discard existing fork guarantees.

- Keep cross-process registry locking alongside expiring credentials and mandatory pairing.
- Keep socket-peer-aware Host and Origin checks alongside the local CLI read credential.
- Preserve scoped pins, terminal colors, native mirror appearance and legacy preferences.
- Preserve cache timestamps, empty terminal reads, password-prompt purging and combined
  snapshot/pane connection reporting while adopting asynchronous saved copies.
- Fetch authenticated journal images under the configured mount exactly once.
- Recognize Claude 2.1.291's plan feedback row as foreign to AGY without rejecting ordinary
  conversation that mentions Claude.
- Include fork-specific color and update-status strings in the five added dictionaries.

## Review follow-through

The adoption review identified three gaps in the imported pairing lifecycle:

- A registry object with a missing or malformed `devices` array must be an outage, not a
  revocation. Returning a pairing refusal here would trigger the new destructive device wipe.
- A successful pairing must deliver its credential expiry immediately. Offline cache limits
  cannot depend on a subsequent Settings revalidation succeeding.
- Authenticated journal image URLs must be revoked and removed from mounted views when the
  device is wiped or its credential changes. Pending reads must not restore the old cache.

These are corrections to the adopted pairing and cache guarantees, not additional features.
The first combines existing registry coercion with the newly imported wipe behavior; the
other two originate in the imported upstream implementation.

## Authorized cross-tab follow-up

The reported retention was reproduced before changing production code. Three real Chromium
two-tab tests failed because the image remained visible after another same-origin document
removed the token, replaced the token, or sent the existing `collie-wipe` announcement.

The image cache now listens to those existing browser events and calls its existing invalidator.
It revokes object URLs, clears mounted images and links, aborts pending reads, and rejects late
responses. Receivers do not clear shared credentials, run another device wipe, or rebroadcast.
Unrelated preference changes and session-storage events are ignored. No new messaging protocol
or wider cache rewrite was added.

Validation of source tree `8f00ecaf9a84d210467dd9c1de6f8920d8c0f34b`:

- Full frontend suite: 20,500 pass, 33 expected failures, 44 TODOs across 372 files.
- Journal-image browser suite: 20 pass on Chromium phone/tablet, including all six two-tab cases.
- Full-tree lint, production build and typechecks pass.
- Two independent, narrowly scoped reviewers reported no findings.

The original cross-tab journal-image limitation is resolved. Backend and whole-browser suite
results in the earlier table were not rerun for this frontend-only follow-up.

## Remaining limitations

- After local image-cache invalidation, an already mounted image stays blank until its source
  changes or it remounts. This avoids silently refetching the wiped image.
- The offline integration implementer flagged other upstream runtime caches in `api.ts`,
  `pane-prefetch.ts` and `liveness.ts` for future wipe-lifecycle examination. These are
  provisional concerns, not confirmed merge regressions or completed audit findings.

## Release boundary

The integration leaves the last released fork version unchanged.

`herdr-plugin.toml`, both package manifests and the newest numbered changelog heading remain
`1.17.0+ys.1`. The adoption is recorded under `Unreleased`, with imported upstream changelog
sections explicitly marked as upstream history. A separate release commit may cut
`1.18.1+ys.1` after validation.

The Herdr 0.8.0 minimum, fork-only update selection and manual source-only publication remain.
No release workflow or Nix lockfile change is part of this adoption. Windows binaries and VM
validation remain upstream-only. This integration does not deploy or restart a running bridge.

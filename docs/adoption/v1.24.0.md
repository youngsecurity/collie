# Upstream v1.24.0 adoption

Issues: youngsecurity/collie#103, #104, #105, #109, #112, #113, #114 and #116.

## Pinned integration

This merge adopts one immutable upstream commit onto one immutable fork base, directly on `dev-joe`.

- Fork base: `1fcc4a6cbe53d77101bf32fc85294ef21ed6ba0f` (`1.22.5+ys.4`).
- Upstream: `4bab157edb527266837dd9dd20b67e1ac82efcae` (`v1.24.0`).
- Integration is a two-parent merge, not a squash or a replacement checkout.
- One merge closes eight sync issues. Upstream kept a Stable maintenance line for 1.23.1 through
  1.23.4 that `v1.24.0` does not descend from, but every fix on that line was re-landed on upstream
  `main` before 1.24.0 was cut (upstream's `docs/upgrading.md`: "If you come from 1.23.4, nothing
  needs doing"). The 1.23.x tags are therefore not merged a second time.
- The one commit upstream `main` carries past `v1.24.0` is `chore(packaging): track 1.24.0`
  (`e2205f47`). The fork does not publish AUR or Nix packages, so it is not cherry-picked; #112 is
  covered by the tag merge.
- The release commit that follows this merge takes `1.24.0+ys.1`. Both release histories remain in
  `CHANGELOG.md`; imported releases use `## Upstream [...]` headings.

## Adopted behavior

1.24.0 brings the large-screen layout (sidebar beside a strip of panes, ADR 0120), pane navigation
by two fingers or a joystick (ADR 0121), usage dots and a Stop button, the Sent view and its
suggestions (ADR 0107), walky talky across the crew, paste chips in the composer, CJK column
alignment in the mirror, the Agents pill, Harness configuration switches, and the Edge/Stable
release lines (ADR 0110). Themes gain the optional `pane-active` token (schema version 3). Bun's
pin moves to 1.4.4, the first release with the eMudhra revocation.

## Conflict and automatic-merge decisions

Fifty files conflicted. The update and release files were resolved in the fork's favour, the UI
files in upstream's favour unless a fork feature sat there.

| Boundary | Integration decision |
| --- | --- |
| Release lines | Upstream's `lineOffer` (`bridge/update-line.ts`) is now the one resolver behind the banner and the `update` verb. On this fork it first cuts the tags to the install's release family (`releaseFamily`) and orders with `compareRelease`, so a `+ys` install sees `+ys` tags only and `+ys.2` supersedes `+ys.1`. Upstream's Edge tags are bare, so a fork install never sees them on either line. `--line` and `--downgrade` are accepted as upstream spells them. |
| Pinning a tag | `--to-tag` keeps the fork's family refusal first, then upstream's downgrade, Edge-line and rejected-build refusals. The order check uses `compareRelease`, and an equal target is not refused: the `crew update` lead leg pins the lead to the release it hands out (youngsecurity/collie#24). The lead still starts `collie update --to-tag <tag>`; upstream's unpinned `start()` and its "already current" test are not adopted. |
| Updater guards | `requireHerdrMinimum` (Herdr >= 0.8.0, `min_herdr_version` in the manifest) runs before an update and again from `_apply-update`. The staging lock is released in a `finally` and on a throw before launch (#21). `update.json` keeps the defensive reader (#22) and learns the `action` field. `UpdateConfirmGate` stays beside upstream's rollback, back and line routes. |
| Crew follow | Upstream's step-down rule (a lead's rollback or switch back to Stable moves a member down to that very build, ADR 0110) is adopted, ordered with `compareRelease`; `bareVersion` keeps the `+ys.N` counter. |
| Pairing | Default-on pairing, `COLLIE_PAIRING` opt-out and the Korean strings for the opt-out states stay. Upstream's #512 fix is taken: a failed devices load offers no pairing form, and the no-loader placeholder reads as an error, not as an empty registry. The form still shows only where pairing is enforced or the phone arrived from the QR. |
| Masking | Snapshot masking covers the fork's open asks, Surface, hold and actions and upstream's todo lists and subagents in one pass. Crew forwarding keeps the fork's answer kinds (`answer`, `control`, durable kinds, `diagnostic`) and adds upstream's `sent`. The phone's `fromPhone` steer mark is adopted. The fork's rule that an unpaired phone never persists content was dropped after this release at the operator's decision: `allowHold` and the anonymous-only stores are gone, and an unpaired phone queues sends and keeps its lines like a paired one. |
| Surface read | The fork keeps taking the input frame from the Surface read (a pi question's answer editor reuses the box's frame, 1.22.5+ys.3). Upstream's Muse slash-palette test (#519) expected a refusal naming the command list; the fork answers the generic refusal, and Enter is not pressed either way, so the test's expected sentence is the one line changed. |
| UI | The fork's full-width Chat stays (no desktop column ladder); upstream's `inStrip` bound for the large-screen column is kept. The raw mirror takes upstream's wide-cell painting beside the fork's terminal colour cascade. Wrap-off defaults and the test `displayPrefs()` helper stay; the new `stretchText` field joins them. |
| Publication | `release.yml` stays the fork's read-only verifier; upstream's payload matrix, Edge stamping jobs, website dispatch and package refresh are not imported, and the upstream test block for them is dropped. `check-version.sh` gains upstream's Edge-stamp reading, which does not fire on a `+ys` version. |
| Toolchain | Bun 1.4.4 in `flake.nix`, every workflow pin and `MIN_BUN`. `flake.lock` does not move. The parked Cloudflare experiment takes upstream's lock (MCP client 2.3.1, SDK 1.32.1, above the fork's GHSA-6qxp-vccf-f47h floor) and its overrides follow. |
| Rehearsals | The browser leg, its new crew leg and the Windows VM rehearsal remain opt-in on this fork and are not release gates. |

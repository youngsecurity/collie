## Integration decisions

Preserve both upstream features and the fork's operational boundaries.

| Surface | Decision |
| --- | --- |
| Browser authorization | Keep pairing enabled by default and the explicit host opt-out. Retain independent access gates, masking, credential expiry, and the rule that opt-out content is not persisted for offline use. |
| Updates | Keep `youngsecurity/collie`, `+ys.N` family selection, consent and checkout safeguards, and Herdr 0.8.0 minimum. Import upstream TLS-only peer verification. |
| UI | Keep terminal preferences, scoped pins, offline state and dashboard grouping while integrating the New page, configurable Keys, Voice and durable panes. |
| Publishing | Retain the read-only release verifier and its fork tests. Do not import upstream binary publishing jobs or website notification. |
| CI | Import the durable-example validation job and pin its Bun to the existing 1.4.2 toolchain. No flake change. |
| Changelog | Retain fork release history first and import upstream release sections under `## Upstream` headings. Cut `1.21.0+ys.1` separately after validation. |
| ADRs | Retain both independently authored 0091 documents at their existing paths. The index explicitly labels the browser-pairing record as fork-specific; existing links remain valid. |

## Validation and publication gates

Run both typechecks, full-tree lint, both test suites and the isolated build. Exercise the crew integration suite and both durable examples, including the adapter-to-example tests. Browser checks use isolated fixtures, never a deployed bridge. Record actual results in the pull request.

Before publishing, validate the release commit's version agreement, generate its notes and `collie-release.json`, preserve the source-only update instructions, and attach only that sidecar. A test failure is a blocker until fixed or explicitly accepted by the operator.

The PR targets `main`, which is the default branch and contains the latest fork release. Do not close adoption issues merely because a PR exists. Verify the upstream tags are ancestors of the published release and record whether the adoption has reached main before closing.

## Known dependency advisory

The imported Cloudflare example's separate development dependency graph reports four high-severity package entries from one advisory, [GHSA-wq5f-xc86-pv6w](https://github.com/advisories/GHSA-wq5f-xc86-pv6w): `sharp`, propagated through `miniflare`, `wrangler`, and `@cloudflare/vitest-plugin`. Avoid processing untrusted images with those development tools until their pinned versions are updated and validated.

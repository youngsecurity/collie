## Integration decisions

Upstream's fixes compose with the fork's existing safeguards rather than replacing them.

| Surface | Decision |
| --- | --- |
| In-place updater | Adopt the early busy refusal and lock held through the apply child. Use the fork's `takeLock` exclusive create and check its boolean result, not upstream's overwriting write and read-back. A loser never fetches or starts the child. |
| Lock expiry | Adopt the one-hour maximum hold in CLI and bridge. Preserve the fork's `LockVerdict.stale` value and pass the exact expired lock to `takeLock` as `breakable`. Release an in-place lock only while it still names this process. |
| Crew follower | Adopt the successful-start latch keyed by full tag and run id. Keep fork-counter ordering, same-run continuation, major consent, fresh preflight and tag-resolution checks. A higher `+ys.N` counter is a distinct target. No crew protocol version or transport changes. |
| Release notes | Adopt bounded sidecar notes and the installed changelog reader. Keep the fork cache policy: cache successful readings only, retry absent sidecars next check because manual publication can follow a tag. Remove the auto-merged `held === "absent"` branch, which is impossible with this cache. |
| Browser route | Notes use the existing read-gated `/api/update/check`; they add no route, bypass or separate network fetch. URLs derive from the configured update repository and version, not sidecar text. |
| Update UI | Adopt dismissible failed-crew notices, timestamped dismissals, release notes, the completion link and the smaller session-switcher mark. Bound optimistic crew closes to the observed run and yield to changed bridge dismissal records, so a mounted tab shows later failed retries even when the dismissal request fails or remains pending. This corrects review finding F1 to preserve the original release behavior. Notes render as React text/code nodes, not HTML. The existing shared poll, consent flow, reload handling and scoped pins remain. |
| Recovery instructions | Retain upstream's incomplete-build warning. Express Herdr-managed recovery through `herdr plugin action invoke update --plugin herdr.collie`; other self-updating installs use `collie update`, and packaged installs keep their package manager. |
| Publication | Keep read-only workflow verification and manual source-only publication. The generator adds notes to `collie-release.json`; the existing verifier compares the whole generated document, so the new field is covered without changing publication permissions. |

The eight textual conflicts were `CHANGELOG.md`, `cli/update-run.ts`, `cli/update.ts`,
`cli/update.test.ts`, `scripts/release-reading.test.ts` and the three version files.
Both fork and upstream test cases were retained. The upstream race test now injects the rival
at exclusive creation, the fork's real acquisition boundary, rather than at an overwriting write.

## Regression coverage

New tests exercise interactions between upstream changes and fork behavior, not only source strings.

- `cli/update.test.ts`: a rival wins exclusive creation before fetch; unreadable acquisition
  failure still refuses; an expired live-pid lock is reclaimed exclusively and released.
- `bridge/crew/follow.test.ts`: duplicate `+ys` turns are latched while a higher fork counter
  in the same run can continue without waiting an hour.
- `bridge/release-notes.test.ts`: generated fork notes survive parsing, exclude bare-upstream
  and next-major offers, link to the fork, and appear after a missing sidecar is published.
  Reading notes adds no fetch and successful readings remain cached.
- `web/src/components/update-card.test.tsx`: an opt-out response displays fork notes as text,
  preserves an expired credential and its expiry, refuses anonymous persistence and does not
  start or arm an update merely by displaying notes.

- `web/src/components/update-ribbon.test.tsx`: keep the ribbon mounted through dismissal,
  snapshot acknowledgement and a later same-version failure. Cover unacknowledged peers-only
  retries after pending or rejected requests, plus concurrent acknowledgement and late request
  completion without undoing a newer close.

## Dependencies and remaining validation

The adoption changes no dependency manifests, lockfiles or toolchain pins.

Locked root and web dependencies install with native Bun 1.4.2. Nix is unavailable; the repo
explicitly permits native Bun. No tool was installed and no dependency age gate was weakened.

Implementation test results and exact logs live in the coordinator's issue-93 state directory,
in `implementation-report.md`. Full release validation and independent reviews are separate
phases. No deployment, live-agent, Windows VM, browser-device or model-backed speech result is
claimed by this implementation.

The upstream lock policy assumes a live PID in a lock older than one hour was reused. A genuinely
longer build can exceed that bound. The follower latch is process-local, and the in-place path
still records completion only after its child succeeds. Staged/binary paths retain their existing
record-before-handoff protection rather than acquiring the lock for all staging work. These are
retained design limits, not claims of complete crash recovery or universal serialization.
